# 操作界面与交互流程评审

日期：2026-09-06。评审版本：当前工作树 HEAD `3b98104`，不是主目录 main 的其他版本。

结论：有数据时，最小模拟与候选审阅可以成功；首次使用、状态一致性、失败恢复和实验管理尚未形成可靠的完整用户流程。建议先修复会让用户看错股票或误用未来数据的问题，再补全入口与视觉细节。

## 范围和验证条件

- 检查 `etf_strategy/web/static` 仪表盘：首页、ETF 评分、组合模拟、股票行业页、数据管理相关代码。
- 检查 `alphalab/research/static` 审阅页：筛选、候选详情、图表周期、选股/事后模式、组合切换、导航及异常路径。
- 浏览器实际操作使用 Codex 内置浏览器；检查桌面截图与页面可访问性树。
- 当前工作树没有可直接使用的真实 ETF/股票行情库。用 `/tmp` 和系统临时目录中的隔离数据库验证空数据与合成数据场景，未修改用户行情库或交易账本。
- ETF 使用项目自带 `generate_sample_data()`：8 只、2080 条日线。审阅使用现有集成测试样本：2 只股票，small/large 两个组合，3/5 日观察周期。
- 未实际运行外部行情同步、真实全市场大数据性能测试、实盘交易或移动设备操作。同步流程结论来自代码检查。
- 执行 `/opt/miniconda3/bin/python -m pytest -q`：**120 passed in 51.37s**。这不等于浏览器交互全部通过。

## 问题清单

### 1. P1：切回选股模式失败时，未来信息仍然显示（浏览器复现）

复现：先进入事后评估并显示收益，停止隔离测试服务，再点击选股审阅。页面提示已经变成“后端响应在有效信号日截止”，但个股未来收益卡片与旧图表没有清除。

原因：`switchMode` 立即更新 mode、按钮和文案，只立即隐藏 portfolioSummary；evaluationSummary 和图表依赖下一次 `renderDetail` 更新。请求失败只显示错误，旧内容继续可见。`selectSymbol` 也没有校验响应是否仍对应当前股票、模式、周期和组合，因此慢请求返回顺序同样有风险；乱序场景本轮没有专门注入延迟复现。

建议：切换模式时立即清除/隐藏不允许展示的数据，进入明确加载态；只接纳当前请求上下文的响应；失败时保留安全空态和重试按钮。将“评估→选股失败”和响应乱序加入浏览器回归测试。

位置：`alphalab/research/static/app.js:271`、`:281`。

### 2. P1：筛选列表、详情、导航计数不一致（浏览器复现）

复现：初始自动选中 300468；搜索 002104。左侧只剩 002104，右侧仍是 300468，位置仍显示 `1 / 2`；筛选结果计数变成 `1 / 1 只`，全量分母也丢失。

原因：loadCandidates 覆盖 state.candidates，只在 selectedSymbol 为空时自动选中，不检查它是否还在筛选结果中，也不刷新详情导航。renderCandidates 的分母和分子均取筛选后的集合。

建议：当前选中项被筛掉时，自动选中新列表第一项，或者清空详情并提示重新选择；无结果时同步清空详情和禁用上下项。分开保存总数与筛选结果，显示“1 / 2 只”。

位置：`alphalab/research/static/app.js:91`、`:126`、`:260`。

### 3. P1：新用户缺少可操作的数据准备流程（浏览器复现）

空库被正常初始化后，首页显示“已读取”、`null`、`NaT`。模拟按钮可点击，结果却只是“暂无模拟结果”。用户无法区分未配置行情、筛选为空、历史不足与运行失败。

建议：首页增加数据准备状态，显示已绑定数据源、覆盖日期及满足研究要求与否；提供明确的初始化/绑定入口和演示数据入口。缺数据时禁用依赖操作并给出下一步，不把请求成功当成业务就绪。

位置：`etf_strategy/web/static/app.js:136`、`:213`、`:418`。

### 4. P2：三个主要实验动作是可点击占位按钮（点击及代码确认）

“权重配置”“保存为实验”“与历史实验对比”共用一段提示，没有真正的配置、持久化或对比操作。用户进入研究流程后无法通过当前界面保存和复用结果。历史审阅服务又要求先通过 CLI 生成并指定 run_id，两套界面之间缺少可发现的衔接。

建议：未完成时明确标成“暂未开放”并禁用；随后打通“配置→运行→命名保存→历史运行列表→审阅/比较”，保存后直接显示运行 ID 与结果入口。无需把重跑功能强塞入只读审阅页。

位置：`etf_strategy/web/static/app.js:129`；`alphalab/README.md` 中 research run/review 启动流程。

### 5. P2：Forward Test 导航指向隐藏区域（浏览器复现）

默认选股模式中点击左侧 Forward Test，只更新锚点，没有显示目标区域。导航外观与正常入口一致，点击结果却不可见。

建议：该入口应明确触发进入事后评估并在加载完成后定位，或在选股模式中显示“进入事后评估后可查看”的解释。让模式切换和导航共用状态逻辑。

位置：`alphalab/research/static/index.html:29`。

### 6. P2：股票页的数据操作仍受 ETF 数据控制（浏览器与代码确认）

测试中 ETF 数据已到最新、股票库为空；进入 Stock Scoring Lab 后显示“暂无股票数据”，侧栏仍是 ETF 的 ACTIVE INSTRUMENT，且“更新数据”被禁用。后端更新接口只执行 update_etf_data.py，并仅依据 ETF 最新日期决定是否需要更新。

建议：数据操作按 ETF/股票市场显示独立覆盖与状态；按钮明确说明更新对象；股票无数据时提供股票数据准备入口。股票页隐藏无关 ETF 标的选择器。

位置：`etf_strategy/run_dashboard.py:488`；`etf_strategy/web/static/app.js:199`、`:213`。

### 7. P2：行情更新缺少失败恢复与过程反馈（代码检查，未实际调用外部同步）

updateData 使用 try/finally 而没有 catch；事件回调没有兜底处理 rejection。失败时按钮会复原，但“正在更新行情”状态可能残留。后端同步等待 subprocess，最长 900 秒；前端也没有阶段进度、任务状态查询或取消入口。

建议：捕获并展示可理解的错误和重试动作；较长更新使用任务 ID、阶段进度与结果摘要，标明成功/失败标的数量与实际覆盖，而非只显示开始/结束。更新任务应避免服务端重复并发执行。

位置：`etf_strategy/web/static/app.js:199`；`etf_strategy/run_dashboard.py:513`。

### 8. P2：桌面审阅布局隐藏了决策所需信息（截图观察）

约 1265px 宽的浏览器中，左侧候选表分配宽度仅约 300px，九列需要横向滚动，总分、权重、状态不能同时看到；摘要的研究日期范围和数据质量文本被省略。右侧还保留较大图表区域，使“比较候选→查看详情”反复需要滚动与切换视线。

建议：默认候选列表保留代码/名称、排名/得分和状态，把完整因子移至详情；支持调整列表与图表的宽度。日期、质量等关键字段允许换行或提供完整值提示；统一主要中文操作文案，并解释 COMPLETE、UNKNOWN 等状态。

位置：`alphalab/research/static/styles.css:75`、`:85`、`:88`。

## 进一步改进与验收建议

1. 优先保证页面上“我选的是谁、当前是什么模式、数据截止哪天、结果属于哪个组合”始终一致。
2. 为候选加载、模拟运行、数据同步分别设计加载/成功/空结果/失败状态，错误附近提供重试，不只在页面末尾放错误条。
3. 图表提供十字光标对应的日期、OHLC、成交量、EMA 数值说明；保持缩放状态，侧栏折叠或窗口变化后重新适配宽度。当前审阅代码每次绘图都 fitContent，且没有尺寸变化监听。
4. ETF 表格展开操作补充键盘入口与 aria-expanded；审阅模式按钮补充可访问的选中状态。导航恢复可保存到 URL，避免刷新后丢失上下文。
5. 增加少量真正覆盖用户行为的浏览器测试：空库首启；搜索→选中→下一只；无结果；评估→选股正常/失败/乱序；模拟→展开→交易解释；保存功能状态。

建议修复顺序：1、2（结果可信）→3、6（能开始操作）→4、5、7（能完成和恢复）→8 及其余视觉/键盘优化。

本次只新增评审文档，未修改业务实现。测试进程与测试浏览器在评审完成后关闭。

## 补充：用户目标“新建股票组合，选择 2021～2025 年任意起止区间进行模拟”

针对这个目标，当前版本的验收结论是 **不通过，尚无完整操作路径**。前述“最小操作通过”仅证明预置 ETF 方案和已生成的股票研究结果可运行/审阅，不能推导为这个目标已支持。

逐步核查结果：

- 股票页只有行业层级、排序、搜索及行情概览，没有新建组合、选股加入组合、设置权重和保存的表单。
- Portfolio Lab 是 ETF 的预置滚动模拟，只提供“最近 N 天”；后端以数据最新日期减 N 天计算区间，不支持用户在页面输入任意起止日期。
- 股票研究 CLI 的 `research run --help` 实际提供的是 `--as-of` 历史信号日与 `--horizons` 交易日观察周期，没有起止日期式回测参数。
- CLI 的 `--portfolio id=initial_cash` 配置独立本金；PortfolioSpec 提供资金、权重方式及约束，不是手动添加股票清单的组合编辑器。
- 历史审阅页面明确只读，不能创建或重跑。
- 当前评审环境没有完整真实行情库，不能证明 2021～2025 年区间已具备所需数据。

建议以该真实用户目标作为首要验收用例，补齐“新建股票组合→手选股票/规则选股→设置本金与权重→选择起止日期与持有/调仓方式→数据预检→运行→结果与保存”。日期预检要分别说明用户区间、实际交易日起止、预热行情覆盖、缺失标的，以及可以执行的修复操作；不得静默缩短区间或以合成行情替代真实历史后展示为成功。
