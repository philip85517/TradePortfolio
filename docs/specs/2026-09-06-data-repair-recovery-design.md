## 已核实的现状

1. `wizard_backend.py::_inspect` 将 volume 缺失和非正值合并为 UNTRADABLE，规则窗口内任意 amount 为空即报 MISSING_FACTOR_FIELD；没有输出对应异常日期与状态证据。
2. 同一股票的零成交量与空成交额可能源于同一事件，现有诊断无法证明或排除这一点。
3. `_prepare` 根据 coverage 状态下载，INVALID 会触发整只股票相关区间重取；缺少针对停牌、退市、来源能力不足的动作分类。
4. `wizard.js::gates` 在数据未就绪且无任务时允许补数，不判断是否存在可执行修复项。页面平铺全部问题和逐股覆盖卡片。
5. `workflow.py` 已持久化草稿、任务和部分完成状态，支持重启恢复及提交前校验，应复用。
6. 新版已获取未复权建仓价并将复权价格路径按该锚点换算；这改善整手核算，但不等于完整公司行为和退市账户核算。
7. 当前 BaoStock 行情请求字段不含 tradestatus。不能仅凭 volume=0 宣称已证实停牌。

基线验证：向导后端和工作流集成测试 42 passed。用现有真实适配器接口的内存夹具将单日 volume 改成 0，两次 inspect 均返回同一 BLOCKED 与“补齐所需数据”建议，证明重复检查本身不会推进恢复；该夹具不证明用户各股票的真实停牌状态。

## 方案选择

| 方案 | 收益 | 局限 |
|---|---|---|
| 只改文案、折叠错误 | 改动少 | 后台仍会无效重取，缺少可信恢复路径 |
| 异常分类、修复计划、动作化页面（推荐） | 保留现有向导与任务机制，让每个操作有明确对象和结果 | 需要调整诊断返回结构与任务记录 |
| 同时实现停牌估值、复牌交易与退市清算 | 扩大可回测范围 | 改变回测语义，需独立数据与账户模型验证 |

本轮选择第二项。第三项作为独立后续能力，不能承诺本轮让所有历史组合通过。

## 诊断模型

检查器输出结构化 issue，中文 message 仅用于展示，不用于业务判断。保留既有 code/message/action 以兼容旧消费者，新增 schema_version、issue_id、symbol、phase、date_ranges、affected_rows、category、severity、evidence、resolution、blocking_scope。

- phase：身份、预热、信号、建仓、持有、退出。
- category：数据缺失、数据冲突、已确认市场事件、状态待核实、来源能力不足。
- evidence：来源、读取时间、原始字段摘要和数据指纹；未知保持未知。
- resolution：可下载修复、需核实状态、需用户选择、当前不支持、无需处理。
- issue_id：基于代码、标的、阶段和日期范围的稳定身份；证据指纹单独保存，便于比较修复前后。
- blocking_scope：整个研究、单个候选资格或单个选中持仓；本轮保持现有候选门禁，不自动跳过异常候选。改变资格策略须另外冻结规则版本。

交易日与上市区间先确定需求范围：休市及已确认上市前日期不计缺口。已确认退市后的缺口不能生成下载计划；若选中股票持有期跨退市，保留“不支持清算”的阻断。

| 情况 | 分类与动作 |
|---|---|
| 交易状态正常，但必要行情／量额字段缺失 | 下载缺失字段对应的最小可用分片，复检 |
| volume=0 或空，状态未知 | 先查询并持久化交易状态；不能直接当作停牌或可交易 |
| 来源证实停牌 | 停牌事件；现有 V1 能力不支持的阶段仍阻断，不反复下载 |
| 同日零量与空额均由已证实停牌解释 | 展示一个事件及两个关联字段，保留原始事实 |
| PIT 行业证据不足 | 明示当前来源能力；提供历史来源配置说明或显式切换探索 |
| 复权口径冲突 | 核实元数据，必要时重取一致口径的完整需求分片；禁止只修改标签 |
| 来源请求超时／连接失败 | 有限自动重试，保留成功分片，允许手动重试失败项 |
| 来源重复返回相同无效数据／空结果 | 保存尝试证据，结束自动重试，标为来源未解决；允许显式重新尝试 |

成交额不以“后复权价 × 成交量”伪造。探索模式仅影响明确列出的 PIT 限制，不解除行情、成交价和执行能力要求。历史上市状态与历史行业分别展示，不把“有上市日期”表达为“完整 PIT”。

## 修复计划与后台边界

建议新增 `data_readiness.py` 承载诊断类型、需求分类及汇总，`data_repair.py` 承载计划与执行；`wizard_backend.py` 继续负责数据加载、研究适配和冻结入口，避免继续扩大单个检查函数。

数据流：范围与版本 → 需求计划 → 只读检查 → 诊断与修复计划 → 执行指定动作 → 重新检查 → 新就绪凭据。

1. repair_plan 包含 plan_id、scope/revision、requirement_id、原始数据指纹和有序动作；动作包含标的、日期、数据类型、来源、原因及目标缓存。
2. 计划可以分阶段：先核实状态，再根据证据决定是否下载。待核实不能被计为已知可修复数量。
3. 后端决定可执行动作，前端只提交计划身份；过期计划或范围变化必须重新检查，不能继续执行陈旧计划。
4. 检查保持只读；网络获取和缓存写入属于准备任务。来源尚未提供交易状态能力时，明确保留未解决项。
5. 行情分片先暂存和校验，再原子合并到修复缓存；不破坏已有有效分片。复权一致性决定是否扩大下载区间。
6. 保存每个动作的请求范围、来源响应摘要、前后指纹、结果、尝试次数和未解决原因。请求成功不等于修复成功。
7. 同一自动动作每次任务最多三次网络尝试，使用短退避；内容无变化且仍无效时不再自动循环。用户显式重试创建新尝试记录。
8. 修复后的覆盖、身份或规则排名变化，重新生成下一阶段计划；沿用现有冻结原始信号输入和数据身份机制，旧预览作废。
9. 复用现有任务生命周期。SUCCEEDED 表示该准备任务使数据达到 READY；有已保存进展但仍有阻断时为 PARTIAL；无进展且执行失败为 FAILED。没有可执行动作时不创建空任务，直接显示检查结果。
10. 取消保留已验证分片，未完成暂存不发布；重启恢复为 INTERRUPTED。重新打开后先查询任务状态，网络读取失败显示“状态暂不可获取”，不冒充任务完成，也不自动创建重复任务。

## 页面与恢复交互

保留五步向导，第二步改为问题工作区。顶部始终显示“当前结果、已保存进展、下一步动作”，操作区不随长列表滚走。

- 概览区：已就绪股票数、待核实事件数、可修复缺口数、需选择／不支持问题数；明确数量单位，不混用股票、日期和问题条目。
- 问题按“可自动处理”“需核实”“需要你处理”分组，默认仅展开阻断项摘要，支持按类型、股票、阶段筛选及展开日期证据。
- 逐股明细分页，默认每页 25 只；原始诊断可导出，避免几百条重复文案占满页面。
- 存在下载动作：主按钮“修复可处理项（N 项）”；仅需核实状态：“核实交易状态（N 项）”。同时存在时统一“处理可自动处理项”，展示动作明细。
- 无可执行动作：不显示可点击的补数按钮，展示“当前来源无法自动解决剩余问题”。提供“重新检查”“返回修改范围”和适用的“切换探索模式”。
- 切换探索：展示将解除的 PIT 门禁与仍保留的阻断，用户明确选择后保存模式并重检，不默认勾选。
- PARTIAL：展示本轮已修复、未变化、请求失败和剩余不可自动处理项；主动作只重试可重试项。
- READY：主动作“继续配置组合”；有来源失败历史但当前证据已验证通过时，不把旧失败当作新的阻断。
- FAILED／CANCELLED／INTERRUPTED：显示已保留的缓存和草稿，动作分别为重试失败项或重新检查后继续。保留本金与权重输入，但旧预览失效。
- 若建议修改股票／日期，说明会改变实验样本；不自动移除未来退市或停牌股票，不自动缩短持有期，不自动补入替代股票。
- 动态完成消息使用 aria-live；错误与操作可键盘访问，折叠明细保留焦点。页面故障时重新获取状态按钮可用。

本次报告的目标呈现：PIT 来源限制独立一组；153 条无有效成交量先显示“待核实”，149 条缺成交额与同日事件关联后再分类；002336 的退市与日期缺口联合解释；302132 单独展示复权证据与修复动作。只有核实后才能显示精确可修复数量。

## 回测与研究边界

本轮不改变 fixed_v0 的打分窗口、缺失值处理或候选替换规则。即使已确认停牌，现有引擎不能处理时也保持阻断并清楚解释。不能把“修复流程完成”作为放宽回测条件的理由。

后续停牌能力需要单独设计：建仓不可交易如何处置、持有期估值及其陈旧标记、退出停牌如何处理、复牌与公司行为如何衔接；退市另需末次可交易日与清算现金证据。不能以填充 OHLC 代替这些规则。

继续保留新版“未复权建仓锚点＋复权收益路径”的口径说明；不宣称已经逐笔模拟分红、配股或退市账户。

## 验收与实施顺序

1. 分类契约：零量状态未知、已确认停牌、正常交易空额、上市前、退市后、混合复权分别测试；断言具体日期、证据、阻断原因及可执行动作。
2. 修复执行：真实 backend 配合确定性 provider 夹具，验证暂存发布、仅失败项重试、相同无效响应停止循环、成功分片不重复下载、取消与重启恢复。
3. 工作流：范围变化拒绝旧计划，重试幂等，复检更新 readiness，数据改变清除预览；服务端动作与页面按钮一致。
4. 页面：以本次报告的相同规模构造脱敏确定性夹具，验证分组、分页、错误后可操作、探索仅解除 PIT、终态刷新恢复。现有 Node 纯函数测试之外，补浏览器端任务失败与恢复验证。
5. 回测不变量：未知缺口继续阻断、未来停牌／退市不会改变信号排名、原始数据库不修改、历史运行不覆盖，未复权锚点股数和既有收益口径保持一致。
6. 真实来源抽样：在目标服务的真实数据上核实报告中的股票与日期，记录 provider 证据和修复前后差异。夹具测试通过不能替代该项，也不代表全市场数据完整。

推荐先交付诊断与计划契约，再接入补数执行和页面，最后进行故障恢复及真实来源抽样验收。实施前再次确认远端基线并评审本草案。
